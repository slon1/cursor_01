## Решения владельца проекта (не обсуждаются)
1. **Львы могут стоять в одной клетке.** Обмена местами нет: шаг или прыжок на клетку, где стоит другой лев, это обычный ход (прыжок платит `JumpCost` как при любом приземлении). Стартовые клетки львов остаются разными.
2. **Сундук:** больше не препятствие. Лев входит в клетку сундука как в обычную. Когда **оба** льва одновременно стоят на клетке сундука, сундук забирается автоматически (предмет исчезает, `ChestTaken`). Если один лев вошёл и вышел до прихода второго, ничего не происходит.
3. **Выход:** тоже больше не препятствие. Выход готов (`ExitConditionsMet`), когда оба льва стоят на клетке выхода, сундук забран и `Gold >= MinCoins`. Победа наступает по нажатию золотой кнопки EXTRACT (`ConfirmExtract`), как сейчас.
4. **Закрытая клетка с сундуком или выходом:** лев входит в неё в том же ходу, в котором она открывается (событие `CellOpened`, затем `LionMoved`). Раньше ход на закрытый сундук только открывал клетку.
5. Всё остальное без изменений: ловушка (лев остаётся на месте, ловушка остаётся, +`TrapCost`), решётка (лев А блокирован, лев Б ломает +`GateBreakCost` и остаётся), золото, рубильник, прыжок, стоимости, поражение при `Alarm >= AlarmThreshold`.

## ЧАСТЬ A. Game.Core
- `RulesEngine.Move`: удали ветку обмена львов и событие `LionsSwapped`. Удали отклонение `TargetIsChest` и правило «партнёр смежен с сундуком».
- Обработка клетки назначения (`ResolveLanding`): сундук и выход обрабатываются как пустая клетка (лев входит, `LionMoved`). Остальные предметы как раньше.
- После каждого принятого хода: если сундук ещё на поле и оба льва стоят на клетке сундука, сундук забирается: `Item = None`, `State.ChestTaken = true`, событие `ChestTaken(pos, lion)` (lion = лев, чей приход завершил условие).
- `ExitConditionsMet`: `lionA == exit && lionB == exit && ChestTaken && Gold >= MinCoins`.
- `ConfirmExtract`: при `ExitConditionsMet` как раньше; иначе отказ без изменений.
- Событие `ExitAttempted` удали (готовность выхода вычисляется состоянием, `GameSession.ExitReady` остаётся). `RejectReason.TargetIsChest` удали; `GateBlocksLionA` остаётся (открытая решётка для льва А).
- Порядок событий хода: `CellOpened` (если клетка была закрыта), `LionMoved` (если лев сменил клетку), эффект предмета (`GoldCollected`, `LeverUsed`, `TrapTriggered`, `GateBlocked`/`GateBroken`), `ChestTaken` (если забран), один `AlarmChanged` (если изменилась), `GameLost` (если порог).
- `GetTargets`: клетка партнёра и клетки сундука и выхода это обычные цели. Исключения только прежние видимые: открытая решётка для льва А.
- `GameState` и `GameSession`: проверь места, где предполагалось, что позиции львов разные; ничего больше не меняй. `LevelData.Validate`: стартовые клетки по-прежнему различны.
- Добавь в Core чистую функцию `TokenSlots.GetSlot(LionId lion, CellPos posA, CellPos posB)` → `TokenSlot { Center, Left, Right }`: `Center`, если львы в разных клетках; в общей клетке `Left` для A и `Right` для B. (Нужна для экрана в 7B; тесты обязательны.)

## ЧАСТЬ B. Решатель (LevelSolver)
- Победа: после хода состояние удовлетворяет `ExitConditionsMet` (затем `ConfirmExtract`). Стартовое состояние не выигрышное.
- Ключ состояния упрощается: открытость клеток теперь не влияет НИ НА ЧТО (закрытый или открытый сундук, выход, решётка, ловушка ведут к тому же исходу). Ключ: позиции обоих львов, маска убранных предметов (золото, рубильник, сломанные решётки, сундук), тревога (в `FindAny` с доминированием по тревоге, как сейчас). Бит открытости сундука из ключа убрать. `Apply` собирает состояние из ключа, клетки без значимого бита закрыты.
- Обнови инварианты в ADR (см. часть F): единственное исключение прежнего инварианта (закрытый сундук нужно было сначала открыть) исчезает.
- `MinSolvableThreshold`, `FindAny`, `Shortest` работают как в 6B.

## ЧАСТЬ D. Тесты
Перепиши или удали все тесты, опирающиеся на обмен, смежность сундука и выхода, `TargetIsChest`, `ExitAttempted`, `LionsSwapped`. Добавь быстрые тесты:
