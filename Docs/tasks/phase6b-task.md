## ЧАСТЬ 0. Решатель: канонизация ключа и метрика `MinSolvableThreshold`
**Идея.** Открытость клетки влияет на исход только для **сундука** (закрытый сундук нужно сначала открыть шагом, потом забрать). Для остальных клеток (пустая, золото, рубильник, ловушка, решётка, выход) открытый и закрытый вариант дают тот же исход:
- золото, рубильник, пустая: лев входит в клетку в обоих случаях;
- ловушка: срабатывает в обоих;
- решётка: лев Б ломает в обоих, лев А не проходит в обоих (в закрытом случае ход «только открывает», в открытом отклоняется, состояние без изменений, кроме самого бита);
- выход: при ходе на закрытую клетку она сначала открывается, и только потом проверяется `ExitConditionsMet`, то есть результат тот же.
Поэтому в ключе состояния бит «открыта» достаточно хранить **только для клетки сундука**; маску открытых клеток убрать. Расчёт `Gold` и остальное не меняется. Это сильно сокращает пространство состояний (на моём порте: уровень 2 с 46 000 до 435 состояний, 6×6 решается за секунды).
Реализуй в `FindAny` и `Shortest` (`LevelSolver`). Ходы по-прежнему делает только `RulesEngine`; при сборке состояния из ключа клетки без значимого бита заполни как закрытые.

**Метрика.** `LevelSolver.MinSolvableThreshold(LevelData level, int maxThreshold, SolveOptions options)`: наименьший `AlarmThreshold` от 1 до `maxThreshold`, при котором `FindAny` находит победу, иначе `-1` (непроходим или `Truncated`). Для этого `LevelData` должен позволять копию с другим порогом (`WithAlarmThreshold(int)`); `GameState`, `GameSession` и правила не менять.
`Tools/Levels/Verify All Levels` печатает для каждого уровня: `Solvable`, ход решения, `AlarmAtWin`, состояния, мс и **`MinSolvableThreshold`**.

**Тесты (быстрые):** канонизация даёт те же результаты на малых картах (проходимая, непроходимая, обрыв по лимиту, только закрытый сундук: нужен шаг-открытие, затем взятие); `MinSolvableThreshold` на карте с известным ответом (например, одна решётка между львами и целью даёт `3 + 1 = 4`); все старые тесты решателя зелёные. `Shortest` на уровнях 1–3 теперь, возможно, укладывается в лимит: если да, запиши `MinMoves` в отчёт; если нет, как раньше `Truncated` не ошибка.
