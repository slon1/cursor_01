## ЧАСТЬ 2. Новый решатель
Требования: найти решение за секунды и вернуть сам путь.

### Интерфейс
- `SolveOptions { SolveMode Mode; int MaxStates = 5_000_000; int TimeLimitMs = 60_000; }`, `enum SolveMode { FindAny, Shortest }`.
- `SolveResult`: прежние поля (`Solvable`, `Truncated`, `MinMoves`, `StatesExplored`) плюс `IReadOnlyList<SolverMove> Path` (`SolverMove { LionId Lion; CellPos Target; }`, если победа найдена; последнее действие пути это ход, после которого `ExitAttempted(true)`; EXTRACT отдельным элементом не пишется), `int AlarmAtWin` (тревога в конце найденного пути), `long ElapsedMs`. Поле `MinAlarmAtWin` переименуй в `AlarmAtWin` (честное название: тревога на найденном пути, а не минимально возможная).
- Старый вызов `TrySolve(LevelData, maxStates)` оставь как обёртку над новым (режим `Shortest`), чтобы не ломать вызовы.

### Алгоритм `FindAny`
- Поиск «лучший-первый» (A* с взвешенной эвристикой, `f = g + 3*h`) или DFS с эвристическим порядком ходов; выбор за тобой, но обоснуй в ADR-009.
- Эвристика `h` (достаточно грубой): пока сундук не забран: расстояние (манхэттен) от каждого льва до клетки, смежной с сундуком; затем до клеток, смежных с выходом; плюс `2 * max(0, MinCoins - Gold)`. Это не обязана быть допустимая оценка.
- Цель: ход, после которого событие `ExitAttempted(true)` (как раньше).
- Проигрышные состояния отбрасывать.

### Компактное состояние
- Без `GameState.Clone()` на каждый ход. Состояние кодируется компактным ключом: позиции львов, `ChestTaken`, `Alarm`, маска открытых клеток, маска «предмет убран» (золото собрано, рубильник использован, решётка сломана, сундук забран). `Gold` выводится из маски. Для поля до 6×6 ключ из нескольких `ulong` (структура с `Equals` и `GetHashCode`, без строк).
- Допустимо хранить в узлах только ключ и родителя и восстанавливать `GameState` из ключа и `LevelData` перед разворачиванием, либо реализовать применение и откат хода; выбери проще и быстрее. Публичный `RulesEngine` остаётся единственным источником правил (никакого дублирования).

### `Shortest`
- Режим для ручного запуска (может быть медленнее): BFS по тому же компактному ключу или IDA* с той же эвристикой (если допустимая). Лимиты те же. Поддерживает `MinMoves`.

### Цель по скорости
- `FindAny` на уровнях 1–3: меньше 5 секунд на уровень в редакторе. Если не достигнуто, опиши в отчёте узкое место.

## ЧАСТЬ 3. Тесты решателя
- Быстрые: проходимая малая карта (решение найдено, путь через `GameSession` приводит к победе); непроходимая карта (недостижимые сундук и выход: `Solvable == false`, не `Truncated`); обрыв по `MaxStates` (`Truncated == true`); детерминированность (два запуска дают один путь); кросс-проверка `FindAny` на трёх уровнях: путь решателя, проигранный через `GameSession`, заканчивается победой (если общее время тестов больше 10 секунд, пометь `[Explicit]` и `[Category("Slow")]`).
- `Tools/Levels/Verify All Levels` использует `FindAny`: пишет по уровню `Solvable`, число ходов пути, `AlarmAtWin`, состояния, миллисекунды. Добавь второй пункт `Tools/Levels/Verify All Levels (Shortest)`.
