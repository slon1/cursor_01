# ФАЗА 5C. Правило «забрать сундук»

**Роль:** ты исполнительный программист проекта Unity 6000.5. Архитектор — Claude (проверяет через git, смотрит картинки из репозитория).
**Ветка:** `phase/5c-take-chest` (от `main` после мерджа `phase/5b-select-popups`).

**Прочитай перед работой:** `Docs/GAME_RULES.md`, `Docs/adr/ADR-002`, `ADR-005`, `ADR-007`, `Docs/TECH_DEBT.md`, `Assets/Scripts/Core/RulesEngine.cs`.

**Цель:** заменить автоматическое открытие сундука действием «забрать сундук». Меняется только ядро, анимация события в игровом экране, тесты и документы. Карты уровней не менять.

## Решения владельца проекта (не обсуждаются)
1. Сундук больше **не открывается сам**, когда оба льва рядом. Автоматическое открытие удалить целиком.
2. **Забрать сундук:** лев делает ход на клетку с открытым сундуком, и в этот момент другой лев стоит в клетке, смежной с сундуком (4 стороны). Тогда сундук исчезает, а ходивший лев занимает его клетку (как при сборе золота).
3. Пока сундук есть на поле, кнопка EXTRACT активироваться не может. Выход возможен только после того, как сундук забран.
4. Условие готовности выхода: сундук забран, клетка выхода открыта, оба льва смежны с выходом, `Gold >= MinCoins`.

## Допущения архитектора (если что-то из этого неверно, отметь в отчёте вопросом, не меняй молча)
- Забирать сундук можно и шагом, и прыжком льва А (приземление на клетку сундука). Стоимость прыжка начисляется как при любом приземлении.
- Сундук на ЗАКРЫТОЙ клетке: ход на неё только открывает клетку (лев остаётся на месте), как сейчас. Забрать его можно следующим ходом. Это позволяет игроку увидеть сундук до того, как его забирать.
- Если другой лев не смежен с открытым сундуком, ход на сундук отклоняется (`TargetIsChest`, без событий и изменений состояния), как сейчас.
- Сундук ничего не даёт (золото не добавляется).

## ЧАСТЬ A. Game.Core
- `GameState.ChestOpened` переименовать в `ChestTaken` (bool). Событие `ChestOpened` заменить на `ChestTaken(CellPos pos, LionId lion)`. Удалить `TryOpenChest` и ветку «CellOpened перед ChestOpened при автоматическом открытии».
- `RulesEngine`, ход на клетку с сундуком:
  1. Клетка была закрыта: открыть (`CellOpened`), принять ход, лев остаётся (как сейчас).
  2. Клетка открыта и другой лев смежен с клеткой сундука: лев перемещается на клетку (`LionMoved`, `isJump` как обычно), предмет убирается (`Item = None`), `State.ChestTaken = true`, событие `ChestTaken(pos, lion)`.
  3. Иначе: отклонить (`TargetIsChest`), без событий и изменений.
- Порядок событий хода: `LionMoved`, `ChestTaken`, затем один `AlarmChanged` (если значение изменилось), затем `GameLost` (если порог). Для прыжка стоимость прыжка включается в `AlarmChanged`.
- `GetTargets`: клетка с ОТКРЫТЫМ сундуком включается в цели, только если другой лев смежен с ней; закрытые клетки по-прежнему всегда включены (содержимое не раскрывается).
- `ExitConditionsMet`: по условию 4 выше. `GameSession.ExitReady` работает через него без изменений.
- `LevelSolver`: в ключе состояния и везде `ChestOpened` заменить на `ChestTaken`; логику победы не менять (ход с `ExitAttempted(true)`).
- Обнови все места, где использовались `ChestOpened` и `TryOpenChest`.

## ЧАСТЬ B. Игровой экран
- `EventPlayer`: вместо пульса на `ChestOpened` обработать `ChestTaken`: жетон льва едет на клетку (событие `LionMoved` уже есть), затем спрайт сундука увеличивается примерно до 1.3 и исчезает (`FadeDuration`), клетка остаётся открытой пустой. Затем обычный `Refresh`.
- Подсветка: цель «сундук» подсвечивается только когда она есть в `Targets` (то есть когда другой лев смежен). Дополнительной логики во View нет.
- Кнопка EXTRACT: логика не меняется, она серая, пока `ExitReady == false`.

## ЧАСТЬ C. Тесты (обязательно)
Обнови существующие тесты сундука и добавь:
- ход льва Б и льва А шагом на открытый сундук при смежном партнёре: сундук забран, лев на клетке, события `LionMoved`, `ChestTaken` в этом порядке, `ChestTaken == true`;
- прыжок льва А на открытый сундук при смежном партнёре: забран, `JumpCost` в тревоге, порядок событий;
- ход на открытый сундук при несмежном партнёре: отклонён, состояние не изменилось, событий нет;
- ход на закрытую клетку с сундуком: только открывается, `ChestTaken == false`, потом забирается следующим ходом;
- партнёр смежен с сундуком по диагонали: не считается (отклонён);
- `GetTargets`: открытый сундук включён только при смежном партнёре; закрытая клетка с сундуком всегда включена;
- `ExitConditionsMet`: false, пока сундук на поле (даже если золото, выход и льва рядом); true после того, как сундук забран;
- ничто не открывает сундук сам: оба льва рядом с сундуком, но ни один на него не ходил: `ChestTaken == false`.
Запусти быстрый набор тестов (без `[Explicit]`).
